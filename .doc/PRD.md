# Product Requirements Document (PRD): Telegram-бот мониторинга фриланс-бирж

## 1. Обзор продукта (Overview)

### 1.1 Назначение
Автоматизированный Telegram-бот для непрерывного мониторинга фриланс-бирж (Kwork, Яндекс.Услуги и др.), первичной фильтрации заказов на основе искусственного интеллекта (LLM Cohere API) и отправки оперативных уведомлений в Telegram при высокой релевантности заказа навыкам исполнителя.

### 1.2 Ключевая ценность
* **Скорость реагирования:** Автоматический опрос бирж раз в минуту с моментальной отправкой уведомлений.
* **Интеллектуальная фильтрация:** Оценка соответствия описания заказа стеку исполнителя с помощью Cohere API, исключающая ручной просмотр нерелевантных заказов.
* **Масштабируемость:** Модульная архитектура, позволяющая подключать новые фриланс-площадки с минимальными затратами.

## 2. Стек технологий и архитектура

### 2.1 Технологический стек
* **Язык программирования:** Python 3.11+
* **Telegram Bot API Framework:** `aiogram 3` (асинхронный фреймворк для Telegram-ботов)
* **Асинхронные HTTP-запросы:** `aiohttp`
* **База данных:** SQLite (файловая БД `orders.db`), асинхронный драйвер `aiosqlite`
* **LLM Интеграция:** Cohere API (модель по умолчанию: `command-r-plus`, библиотека `cohere`)
* **Авторизация/Парсинг:** Использование сессионных Cookie-файлов (передаются через конфигурационный `.env`)

### 2.2 Структура проекта
```text
freelance-bot/
```

## 3. Функциональные и технические требования

### 3.1 Модель данных заказа (`Order`)
Вся информация о найденном заказе инкапсулируется в Python Dataclass `Order`:

```python
from dataclasses import dataclass

@dataclass
class Order:
    title: str          # Заголовок / название заказа
    description: str    # Полное описание задания
    price: str          # Бюджет / стоимость
    deadline: str       # Срок выполнения
    client: str         # Имя / профиль заказчика
    source: str         # Источник ("Kwork" / "Яндекс.Услуги")
    url: str            # Уникальная ссылка на заказ (служит уникальным идентификатором)
```

### 3.2 База данных (SQLite)
* **Файл БД:** `orders.db`
* **Таблица:** `orders`
* **Поля таблицы:**
  * `id` (INTEGER PRIMARY KEY AUTOINCREMENT)
  * `title` (TEXT)
  * `description` (TEXT)
  * `price` (TEXT)
  * `deadline` (TEXT)
  * `client` (TEXT)
  * `source` (TEXT)
  * `url` (TEXT UNIQUE) — уникальный индекс для исключения дубликатов
  * `relevance` (INTEGER) — процент совпадения (0–100), рассчитанный LLM (Cohere)
  * `created_at` (TIMESTAMP) — время сохранения записи в БД

### 3.3 Абстракция бирж (`exchanges/base.py`)
Каждая фриланс-биржа реализуется как отдельный модуль, наследующий базовый абстрактный класс `Exchange`:

```python
from abc import ABC, abstractmethod

class Exchange(ABC):
    name: str

    @abstractmethod
    async def fetch_orders(self, session) -> list[Order]:
        """Возвращает список свежих заказов с биржи"""
        pass
```

Добавление новой биржи осуществляется путем создания нового файла в папке `exchanges/` и регистрации созданного класса в списке `EXCHANGES` в `config.py`.

### 3.4 Переменные окружения (`.env`)
Система настраивается через следующие параметры:

| Переменная | Описание | Пример значения |
| :--- | :--- | :--- |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота из BotFather | `123456789:ABCdefGhI...` |
| `TELEGRAM_CHAT_ID` | ID чата/пользователя для уведомлений | `987654321` |
| `COHERE_API_KEY` | Ключ доступа к Cohere API | `your_cohere_api_key_here` |
| `COHERE_MODEL` | Название модели Cohere | `command-r-plus` |
| `MY_SKILLS` | Навыки пользователя для оценки | `Python, веб-разработка, React, ...` |
| `RELEVANCE_THRESHOLD` | Минимальный процент релевантности для уведомлений | `70` |
| `POLL_INTERVAL_SECONDS` | Интервал опроса бирж в секундах | `60` |
| `KWORK_COOKIES` | Куки авторизации для Kwork | `PHPSESSID=...` |
| `YANDEX_COOKIES` | Куки авторизации для Яндекс.Услуги | `Session_id=...` |

## 4. Алгоритм работы (Workflow)

Основной цикл планировщика (`scheduler.py`) выполняет следующие действия раз в заданный интервал (`POLL_INTERVAL_SECONDS`):

1. **Опрос бирж:** Для каждой активной биржи из списка `EXCHANGES` вызывается метод `fetch_orders(session)`.
2. **Проверка дубликатов:** Для каждого полученного объекта `Order` проверяется наличие его `url` в таблице `orders` БД SQLite.
3. **Фильтрация и сохранение:**
   * Если `url` уже есть в БД — заказ пропускается.
   * Если `url` отсутствует:
     1. Заказ записывается в БД `orders.db`.
     2. Поля `title` и `description` отправляются в `llm.py` вместе с перечнем навыков `MY_SKILLS`.
     3. Cohere API оценивает релевантность заказа от 0% до 100%.
     4. Значение процента сохраняется в поле `relevance` базы данных.
4. **Уведомление:** Если полученный от Cohere API процент `relevance >= RELEVANCE_THRESHOLD` (например, 70%+), через `notifier.py` в Telegram отправляется сообщение со всеми деталями заказа (источник, заголовок, цена, срок, клиент, ссылка и оценка релевантности).

## 5. План реализации (Roadmap)

1. **`.env.example` + `config.py`** — создание шаблона и модуля парсинга/валидации конфигурации (Cohere API).
2. **`requirements.txt`** — спецификация зависимостей (`aiogram`, `aiohttp`, `aiosqlite`, `cohere`, `pydantic` и др.).
3. **`db.py`** — создание структуры SQLite таблицы `orders` и CRUD-функций.
4. **`exchanges/base.py`** — реализация абстрактного класса `Exchange` и датакласса `Order`.
5. **`exchanges/kwork.py`** — создание модуля парсера Kwork (заглушка / логика с авторизацией по кукам).
6. **`exchanges/yandex_uslugi.py`** — создание модуля парсера Яндекс.Услуги (заглушка / логика).
7. **`llm.py`** — клиент Cohere API с промптом для оценки соответствия навыкам.
8. **`notifier.py`** — сервис формирования и отправки сообщения в Telegram.
9. **`scheduler.py`** — бесконечный асинхронный цикл опроса с обработкой ошибок.
10. **`main.py`** — единая точка входа для инициализации бота, базы данных и старта планировщика.

## 6. Стратегия тестирования и проверки

1. **Настройка окружения:** Заполнить `.env` валидными токенами (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `COHERE_API_KEY`).
2. **Установка зависимостей:** Выполнить команду `pip install -r requirements.txt`.
3. **Запуск приложения:** Выполнить команду `python main.py`.
4. **Проверка цикличности:** Убедиться, что бот успешно стартует и каждые 60 секунд опрашивает заглушки бирж без ошибок.
5. **Интеграционное тестирование:** Вручную добавить тестовый заказ через заглушку парсера и проверить:
   * Запись заказа в БД `orders.db`.
   * Корректный вызов Cohere API и получение процента релевантности.
   * Успешное получение уведомления в Telegram-чате при совпадении от 70%.
